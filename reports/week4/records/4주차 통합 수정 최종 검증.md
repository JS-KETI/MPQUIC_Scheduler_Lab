## 4. 구현·경계 검증

- **연결 종료·송신 재개**
  - 수정
    - 전송 중 목록·소켓 미전송량·스트림 미전송량 확인. 강제 연결 종료는 기존 처리 유지
    - ACK 이후 한 개의 이벤트로 스트림 재개. 재진입 방지·연결 상태 재확인·무진전 자동 재예약 방지
    - 재개 후 새 송신을 직접 중복 호출하지 않고 AppendingTx의 기존 송신 예약 이용
  - **검증 결과**
    - **대표 51회 정상 실행, 완료·전체 수신 48/51회. 이전 완료 22/22회 완료·전체 수신 유지**
- **재전송 프레임 보존·분할**
  - 수정
    - 여러 STREAM 프레임 분리, 길이 생략 프레임의 잔여 데이터 해석, 길이 0 종료 표식(FIN) 보존
    - 오래된 ACK·MP_ACK·패딩은 명시적으로 제외하고 MAX_DATA 등 재전송할 제어값 보존
    - 추가 헤더로 바뀌는 옛 바이트 합 대신 실제 재전송 대기 항목이 소진될 때까지 송신
    - 작은 잔여 송신 창에서 나눌 수 없는 제어 프레임은 보관 후 다음 충분한 창에서 전송
  - **검증 결과**
    - **70KB 데이터·두 스트림의 위치/바이트/종료 표식, 제어값, 작은 송신 창, 길이 생략 프레임, 저장 패킷 복사 검증 3개 통과**
    - **기존 스케줄러 단위 검증 4개 통과. 합계 7개**
  - 크기 기준
    - 제한한 크기는 직렬화된 QUIC 프레임 묶음. 뒤에 붙는 새 ACK·QUIC·UDP·IP 헤더를 포함한 전체 패킷 크기와 구분
    - 마지막 재전송 패킷의 남은 공간에 새 데이터가 함께 들어갈 수 있음. 새 데이터 전체를 재전송 루프에서 배출하지 않음

## 6. 통합 검증 중 추가 확인한 송신 호출 문제

- **통제 실험 (ACK 후 추가 송신 호출 있음 → 없음, 전송 조건 유지)**
  - 최초 문제 상황
    - 1차 전체 1,163회는 완료·전체 수신 1,109회. 기존 완료 중 장시간 5회·손실률 1% 2회가 새 미완료로 변경
  - 원인 확인
    - ACK 처리에서 이미 송신한 뒤, 스트림 재개 이벤트가 데이터 이동 여부와 무관하게 송신 스케줄러를 다시 호출
  - 수정
    - 추가 직접 호출 한 줄 제거. 재개 데이터는 기존 소켓 송신 예약으로 처리
  - **검증 결과**
    - **신규 미완료 7회·정상 대조 5회·작은 버퍼 관찰 1회, 총 13회 비교**
    - **장시간 5/5회 전체 수신 회복. 정상 대조 5/5회 유지. 손실률 1% 2회와 작은 버퍼 1회는 미완료 유지**
    - **수정한 코드 버전을 고정한 뒤 원래 1,163회 전체를 다시 실행한 결과가 본 문서의 최종 수치**
- **별도 시간 연장 확인 (손실률 1% 두 실행의 제한 시각 60초 → 300초)**
  - 대상
    - degrade·seed 5의 EAT·MinRTT-multi. 전송량·버퍼·손실률·공통 수정 유지
  - **결과**
    - **2/2회 전체 수신. 전체 수신의 시뮬레이션 시각은 60.2994초·63.8464초로 원래 제한 시각 60초를 초과**
    - **이 시간 연장 결과는 최종 1,163회 완료 수에 포함하지 않음**
  - 최종 전체 검증의 추가 확인 대상
    - 위 두 손실 실행은 시간 제한 초과를 확인. 장시간 2회·추가 손실 3회의 구체적인 미완료 원인은 미확정
