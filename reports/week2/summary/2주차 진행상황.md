## 2. 문제 상황 - 미완료 62회 원인 분석·수정

### 2-1. 원인별 유효 수정 결과 (미완료 62회 모두 전체 수신)

- **중복 수신 처리 수정 (이미 전달한 데이터의 중복 반영 방지)**
  - 원인: 전달이 끝난 중복 데이터로 수신 위치 계산과 실제 전달량 불일치. 미완료 54회 발생
  - 수정: 이미 전달한 범위 제외·실제 추출량만 수신 위치에 반영
  - **결과: 해당 54회 모두 완료 처리·목표량 전체 수신**
- **재전송 판단 수정 (유실된 데이터의 재전송 누락 방지)**
  - 원인: 네트워크 큐(FqCoDel)의 지연 목표 초과로 IPv4 조각 폐기. 재전송 판단이 누락돼 8회 미완료
  - 수정: ACK(수신 확인) 번호가 송신 목록에 없어도 번호 차이로 손실 검사 수행
  - **결과: 해당 8회 모두 완료 처리·목표량 전체 수신**

![그림 4. 동일 조건 630회 수정 전후 결과 (완료 후 10ms 종료 유지)](figures/recovery_counts.png)

- **수정 통합 결과 (동일 조건 630회 재실험)**
  - **완료 처리 630/630회. 목표량 전체 수신 621/630회**
  - 기존 미완료 62회: 제공 seed 1~10의 19회는 기준과 동일. 추가 seed 11~30의 43회는 제공 기준 없음

### 2-2. 남은 확인·다음 작업 (전체 수신 미달 9회·시간 증가 검토)

- **종료 대기 검증 (완료 처리 이후 남은 바이트 수신 확인)**
  - 원인: 완료 후 10ms에 종료해 후속 바이트 수신 전에 측정 종료. 목표량 미달 9회 유지
  - 별도 실험: 대기 10ms → 250ms 변경 후 9/9회 전체 수신. 기록된 완료 시각 동일
  - 기본 10ms 결과의 미달 9회: 기존 미달 5회 + 수정 후 신규 미달 4회
- **전송 시간 변화 (수정 전후 모두 완료한 같은 seed끼리 비교)**
  - 대상: competing·MinRTT-multi의 공통 완료 seed 13개
  - 평균 시간: 3.4185초 → 3.7220초. **0.3035초 증가**
  - 다음 확인: 전송 시간 증가 원인과 남은 9회의 종료 처리
- **게이트 2 (2주차 기준 데이터 확정 조건)**
  - 통과 기준: dominating 평균 전송 완료 시간의 95% 신뢰구간 폭 0.1초 이하
  - 신뢰구간 폭: 반복 측정으로 추정한 평균의 불확실성 범위. 상한에서 하한을 뺀 값
  - MinRTT-multi: 기존 0.0130초 → 수정 0.0257초. 기준 충족
  - MinRTT·ECF·Peekaboo: 수정 후 0.1647~0.1751초. 기준 초과
  - 다음 조치: 기준 적용 대상·사용할 기준선 확정 → 통과 여부 판정 → 3주차 진입 결정
