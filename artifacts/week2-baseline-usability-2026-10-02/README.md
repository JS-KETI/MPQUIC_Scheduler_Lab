# 2주차 기준 데이터의 비교 가능 범위

### 3-3. 기준 데이터의 사용 범위 검토 (competing의 완료율·공통 완료 seed에 제약)

- **기준 데이터 구성: 630회 전체의 완료·미완료·수신량 보존**
  - 시간 평균은 완료 처리된 실행으로 계산. 완료율과 정확한 목표 바이트 수신율은 전체 30회로 계산
  - 이후 새 스케줄러도 같은 30개 seed에서 실행해 완료율·수신량·시간을 함께 대조

| 주 비교 대상 MinRTT-multi | 완료 처리 | 전체 수신 | 기준 데이터의 사용 범위 |
|---|---|---|---|
| dominating | 30/30 | 30/30 | 30개 seed의 완료 시간·완료율·수신량 비교 가능 |
| competing | 13/30 | 11/30 | 완료율·수신량 비교에 사용. 시간 차이는 양쪽이 완료한 seed로 한정 |
| degrade | 30/30 | 27/30 | 코드 완료 시간은 30개 seed 비교 가능. 정확한 전체 수신 여부도 별도 대조 |

- **미완료 집중: competing의 RR·MinRTT-multi·EAT 각각 17/30회 미완료**
  - 세 스케줄러의 완료율은 43.3%. RR의 seed 11~20 구간은 1/10회만 완료
  - dominating의 BLEST는 26/30, ECF는 28/30 완료. 나머지 dominating 조합과 degrade 전체는 30/30 완료
  - 제공 seed 1~10에서는 기존 미달 조합·수신량과 모두 일치. 추가 seed 11~30에는 제공 기준이 없음
- **시간 비교의 제약: 공통 완료 seed가 10~13개로 감소**
  - competing의 MinRTT-multi ↔ EAT: 같은 13개 seed에서 모두 완료, 나머지 17개는 양쪽 미완료
  - MinRTT-multi ↔ RR: 각각 13개 완료지만 공통 완료는 10개. MinRTT-multi ↔ BLEST: 공통 완료 11개
  - ECF·Peekaboo는 30/30 완료했어도 MinRTT-multi와의 시간 쌍비교는 공통 완료 13개만 사용
- **평균 시간 해석: 완료한 실행만 남겨 빠른 것처럼 보이는 현상에 주의**
  - competing의 MinRTT-multi 평균 3.4185초는 완료한 13회 기준. ECF 평균 6.1940초는 완료한 30회 기준
  - 평균 시간과 함께 MinRTT-multi 완료율 43.3%, ECF 완료율 100%를 표시해야 전체 전송 성능을 판단할 수 있음
  - 새 기법이 기존 미완료 seed를 완료하면 완료율 개선으로 기록. 시간 개선은 공통 완료 seed에서 따로 계산
- **95% 수신 진행: competing의 MinRTT-multi는 30/30회 도달**
  - 미완료 실행까지 포함한 30회의 95% 수신 시간 평균은 3.3656초. 완료한 13회만의 95% 수신 평균 3.2614초와 구분
  - 목표 대부분을 받는 속도와 마지막까지 완료하는 능력을 함께 확인. 이 지표가 전체 수신을 대신하지는 않음
- **검토 결과: dominating·degrade는 시간 비교의 주요 기준, competing은 완료율과 완료 시간의 제한된 비교에 사용**
  - competing의 평균 시간만으로 전체 성능 우위를 판정하기 어려움. 공통 완료 seed 수·완료율·95% 수신 시간을 함께 보고
  - 코드의 완료 시간은 목표보다 3,000B 부족해도 기록됨. 정확한 목표 바이트 전체 수신 시간은 현재 CSV에서 별도 계측되지 않음
