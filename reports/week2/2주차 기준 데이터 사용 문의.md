## 2주차 기준 데이터 사용·통과 기준 문의

- **수행 현황:** 3시나리오 × 7스케줄러 × seed 1~30 = 630회 실행. 통계·그림·기준 데이터 동결 완료, 실행 오류·누락 0건
- **제공 기준 대조:** seed 1~10의 210회는 완료 처리 191회·전체 수신 181회로 제공 CSV와 동일. 미달 항목·수신량까지 일치. 추가 seed 11~30의 420회는 제공 기준 없음

### 1. 미완료가 집중된 조건의 평균 시간 비교 방법

| competing 시나리오 | 완료 처리 | 목표 바이트 전체 수신 | 완료한 실행의 평균 시간 |
|---|---|---|---|
| MinRTT-multi (주 비교 대상) | 13/30 | 11/30 | 3.4185초 (13회 기준) |
| ECF | 30/30 | 24/30 | 6.1940초 (30회 기준) |

- **확인 사항**
  - RR·MinRTT-multi·EAT는 각각 17/30회 미완료. 완료한 실행만의 평균으로 전체 성능을 비교하면 미완료 구간의 영향이 빠짐
  - 같은 seed(무작위 조건 재현 번호)에서 두 스케줄러가 모두 완료한 시간끼리 비교 가능한 수: MinRTT-multi↔EAT 13개, ↔RR 10개
  - 완료 처리는 목표보다 3,000B 부족해도 인정되는 코드 조건. 전체 수신은 목표 5,242,880B를 정확히 받은 경우
- **문의 1: 현재 데이터를 기준으로 비교를 진행해도 되는지, 미완료 원인 분석을 먼저 해야 하는지?**
  - 검토안: 630회 전체를 보존하고, 완료율·전체 수신율과 공통 완료 seed의 전송 완료 시간(FCT)을 함께 비교
  - 보조 지표: 목표의 95%를 받는 시간. competing의 MinRTT-multi는 30/30회 도달, 평균 3.3656초
  - 요청서에서 competing 미완료는 알려진 한계이며 원인 추적은 선택 과제. 신규 스케줄러 작업 전 선행 분석이 필요한지 확인 요청

### 2. 2주차 통과 기준의 신뢰구간 적용 대상

- **요청 기준:** dominating 평균 FCT의 95% 신뢰구간 폭 0.1초 이하. 폭은 평균 추정 범위의 상한에서 하한을 뺀 값
- **측정 결과:** MinRTT-multi 0.0130초로 충족. MinRTT 0.1648초·ECF 0.1754초·Peekaboo 0.1683초로 기준 초과
- **문의 2: 위 기준은 주 비교 대상 MinRTT-multi에 적용하는지, 7개 스케줄러 모두에 적용하는지?**
  - 모두 적용한다면 기준 초과 스케줄러의 추가 seed 측정 범위와 기존 동결 데이터의 사용 방법 확인 요청
  - 현재 3주차 진입은 적용 대상 확인 전까지 보류
