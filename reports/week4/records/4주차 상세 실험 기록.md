- **업무 요청서 D16~D20 수행 범위**
  - 대상
    - 열화 시점·강도 변화, 수십 초 이상 긴 전송, 손실·큐·버퍼 변화, 4경로 동작 한계, 재현 패키지와 중간 보고
  - 실험 설계
    - 전송량·설정값·seed 수는 요청서의 고정값이 아닌 이번 측정을 위해 선택한 값

    - 기본 QUIC·혼잡 제어·스케줄러 알고리즘은 변경하지 않음. 5주차 자동 비율 결정은 이번 범위 밖
- **판정 정의**
  - 실행 성공
    - 프로세스 종료 코드 정상, RESULT·필수 계측 출력 존재. 1,163/1,163회

    - FCT는 완료 실행만, FCT95는 전체 실행 중 목표 95%에 도달한 실행만 포함
    - p90 FCT는 완료 시간 분포의 90백분위. FCT95와 다른 지표
    - 쌍비교는 같은 seed에서 두 스케줄러가 모두 완료한 실행의 시간 차이·95% 신뢰구간·Wilcoxon·승패 계산
    - 설정 전후 우열 변화는 두 설정에서 두 스케줄러 모두 완료한 같은 seed를 사용. 공통 seed 0이면 비교 불가
    - 강건성 우열 변화 12건 중 100패킷 큐의 6건은 공통 seed 1개인 경우 5건·2개인 경우 1건. 탐색적 관찰로 기록
  - 기준 대조

    - **RR·EAT·MinRTT-multi·ID 7 기본 모드는 네 경로에 분배**
    - **MinRTT·BLEST·ECF·Peekaboo는 추가 경로에 초기 소량을 보낸 후 경로 0·1 중심으로 전송**
  - 계측 해석
    - PATH4는 같은 소켓이 여러 Config 경로로 열거돼 중복될 수 있으므로 node·flowId·주소로 식별
    - 경로별 STREAM payload는 재전송·중복 포함 송신/수신 합계. 정확 앱 수신량과 별도
    - 4경로 그림의 분모는 경로 0~3 송신 payload 합. 기존 두 경로 IP 비중 필드는 4경로 summary에서 비해당 처리
- **설정·관찰 범위**
  - 손실률
    - 원래 RateErrorModel 기본 단위는 byte. 이번 0.1%·1% 실험은 forward 병목 수신 장치에 packet 단위를 명시. 역방향 ACK 손실 설정 아님
  - 큐
    - 병목 양단 FqCoDel 최대 패킷 수만 변경. 기본 10,240p, CoDel 지연 목표 5ms·장치 DropTail 유지
  - 열화
    - 100ms 간격 갱신. EVENT4는 실행 전에 기록한 예정 격자 시각이며 실제 이벤트 실행 증거가 아님
    - analysis의 event_planned_grid_s와 완료 시각을 대조. late 35회 모두 열화 예정 시각 이후 완료
  - 드롭
    - queue_drops는 계측한 병목 QueueDisc, error_drops는 해당 장치 PhyRxDrop. 전체 네트워크의 모든 폐기로 일반화하지 않음
