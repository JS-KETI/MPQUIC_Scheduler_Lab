## 이슈·커밋

- 작업 이슈: `[Docs] 1주차 주간 보고·실험 코드와 재현 산출물 등록`처럼 유형과 목적을 표시
- 커밋 제목: `[#이슈번호] Type: 한국어 설명`
- 유형: 기능은 `Feat`, 수정은 `Fix`, 문서·보고·인계 자료는 `Docs`
- 커밋 본문: 변경한 내용과 실제 검증 결과를 짧게 기록. 관련 이슈 번호는 실제 존재하는 번호 사용
- 원본 upstream 및 기존 검증 커밋의 메시지·이력을 보존. 이후 새 커밋부터 이 관례 적용

## 브랜치·실험

- 이후 새 작업은 `feat/#번호-목적`, `fix/#번호-목적`, `docs/#번호-목적` 형식 사용
- 기존 분석 브랜치 `lab/w1-one-path-diagnosis-20261001`은 이번 인계에서 이름과 이력을 보존
- 새 저장소 `main`은 현재 검증된 인계 상태. 수정 브랜치·최초 setup 기준 태그를 함께 보관
- 전송·스케줄러 수정은 원인별로 분리하고 같은 조건·seed로 비교
- 원시 CSV·최초 실패·제공 패치를 보존. 관측 계층의 완료 기준과 정확한 목표 바이트 수신을 구분
